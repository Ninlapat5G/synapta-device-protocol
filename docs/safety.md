# ความปลอดภัยและสิทธิ์

อุปกรณ์ SDP ขยับของจริงได้ (มอเตอร์, รีเลย์, ฮีตเตอร์) ความผิดพลาดของ agent จึงไม่ได้จบแค่ในจอ

## สิทธิ์ (โปรดักต์ตัดสินผ่าน hook `authorize` ของ `sdp-host` ไม่ใช่ที่ firmware)

| สิทธิ์ | ค่าเริ่มต้น | ตั้งที่ |
|---|---|---|
| เห็นอุปกรณ์ (list, describe) | เปิด | ต่อ agent เหมือนสิทธิ์ view/control ที่มีอยู่ |
| สั่ง capability ที่ `danger = none` | เปิดเมื่อ agent มีสิทธิ์ control | |
| สั่ง `actuator` / `destructive` | ปิด — เจ้าของเปิดรายอุปกรณ์ | panel หน้า "อุปกรณ์" |
| แฟลช / OTA | ปิด — เจ้าของเปิดรายอุปกรณ์ | panel หน้า "อุปกรณ์" |

- `danger` ที่อุปกรณ์ประกาศเป็นแค่คำแนะนำ — firmware ที่เขียนผิด (หรือของปลอม) บอกว่า `none` ได้ เจ้าของต้องตั้งทับได้
- ทุก call ที่ไม่ใช่ `none` และทุกการแฟลช ลง audit log ของโปรดักต์ที่สั่ง (ใคร, agent ไหน, เมื่อไร, input, ผล)

## Heartbeat และสภาพปลอดภัย

**ปัญหาที่กัน:** agent สั่ง "เปิดปั๊ม" แล้ว PC ดับ / สายหลุด / โปรดักต์อัปเดตตัวเอง → ปั๊มเปิดค้างไม่มีใครปิด

- `sdp-host` ส่ง `ping` ทุก N วินาทีขณะถือพอร์ต (N ประกาศใน `hello_ack` เป็น `heartbeat_ms`)
- firmware lib นับเวลาเอง ถ้าไม่ได้ `ping` เกิน 3 × `heartbeat_ms` → เรียก `on_link_lost()` ที่ผู้เขียน firmware กำหนด
  (ปิดเอาต์พุตทั้งหมด หยุดมอเตอร์)
- firmware lib ทำให้ `on_link_lost` เป็นของที่ **ต้องเขียน** สำหรับอุปกรณ์ที่มี capability `actuator`
  (ไม่มี = คอมไพล์ไม่ผ่าน หรือ describe แจ้งเตือน) **[เปิด]** — เลือกวิธีบังคับตอนทำไลบรารี
- `boot_id` ใน `pong` เปลี่ยน = บอร์ดรีเซ็ตระหว่างทาง `sdp-host` แจ้ง agent ว่าสถานะที่สั่งไว้ก่อนหน้าหายแล้ว
  (ห้ามดูจาก `uptime_ms` ลดลง — `millis()` 32 บิตวนกลับทุก 49.7 วัน)

## ขอบเขตที่ SDP ไม่ทำ

- ไม่ใช่ระบบความปลอดภัยเชิงหน้าที่ (functional safety / SIL) — งานที่คนอาจบาดเจ็บต้องมีวงจรตัดฉุกเฉินแยกจากซอฟต์แวร์

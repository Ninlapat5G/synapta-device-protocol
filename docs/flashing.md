# อัปโค้ดลง MCU

agent เขียนโค้ด → `sdp-host` คอมไพล์บน PC → ส่งลงบอร์ด → ตรวจว่าบอร์ดกลับมาพูด SDP ได้ → รายงาน

## ผ่านสาย (เฟส 1)

`sdp-host` ไม่เขียนตัวแฟลชเอง เรียกเครื่องมือมาตรฐานเป็นโปรเซสลูก:

| ชิป | คอมไพล์ | แฟลช |
|---|---|---|
| AVR (Uno, Nano, Mega) | `arduino-cli compile` | `avrdude` (มากับ arduino-cli) |
| ESP32 / ESP8266 | `arduino-cli` หรือ PlatformIO | `esptool` |
| RP2040 | `arduino-cli` / pico-sdk | `picotool` หรือคัดลอก UF2 |
| STM32 | PlatformIO / STM32Cube | `dfu-util`, `st-flash`, OpenOCD |

**ลำดับที่ต้องทำให้ถูก**
1. ปล่อยพอร์ตจาก registry (ไม่งั้นเครื่องมือแฟลชเปิดพอร์ตไม่ได้)
2. แฟลช — ระหว่างนี้พอร์ตอาจหายแล้วกลับมาเป็นเลขใหม่ (transports.md กับดัก 2)
3. หาอุปกรณ์ใหม่ด้วย VID/PID/serial แล้วส่ง `hello` ภายในเวลาที่กำหนด
4. ได้ `hello_ack` และ `fw` ตรงกับที่เพิ่งแฟลช = สำเร็จ ไม่ได้ = รายงานล้มเหลวพร้อม log ของเครื่องมือ

## เครื่องมือมาจากไหน (decisions #7)

ไม่ฝังในโปรแกรม (ขนาด, license, อัปเดตแยก) ลำดับการหา:
1. **ของที่เครื่องมีอยู่แล้ว** — PATH, Arduino IDE, `%LOCALAPPDATA%\Arduino15` ใช้แบบอ่านอย่างเดียว ไม่อัปเดตทับ
2. **โฟลเดอร์กลาง** `%LOCALAPPDATA%\Synapta\toolchains\<เครื่องมือ>\<เวอร์ชัน>\` — หลายเวอร์ชันอยู่คู่กันได้
3. **ไม่มีทั้งคู่** — ดาวน์โหลดเวอร์ชันที่ล็อกไว้ ตรวจ hash แล้วลงโฟลเดอร์กลาง

เวอร์ชันที่ใช้: โปรเจกต์ firmware ระบุในไฟล์ของโปรเจกต์ (เช่น ESP32 core 2.0.17 สำหรับโค้ดเก่า) ไม่ระบุ = ค่าเริ่มต้นของเครื่อง

**tool ของ agent:** `toolchain_list` (ของระบบ + โฟลเดอร์กลาง), `toolchain_install`, `toolchain_use` (ผูกเวอร์ชันกับโปรเจกต์), `toolchain_remove`
— install/remove ผ่าน `authorize` เหมือนการแฟลช เพราะเป็นการดาวน์โหลดและรันโปรแกรมภายนอก

**กับดัก:** สองโปรดักต์สั่งลงเวอร์ชันเดียวกันพร้อมกัน → ลงในโฟลเดอร์ชั่วคราวแล้ว rename เข้าที่ทีเดียว
ไม่งั้นอีกตัวเห็นโฟลเดอร์ครึ่ง ๆ แล้วเรียกใช้ของที่โหลดไม่เสร็จ

## ไร้สาย (เฟส 2–3)

สำหรับ ESP32 บน ESP-IDF ใช้ [เครื่องมือ OTA ปัจจุบัน](esp32-ota.md) เพื่อส่ง image ที่เซ็นแล้วผ่าน Wi-Fi และตรวจผลหลังบูต

| ทาง | ใช้กับ | หมายเหตุ |
|---|---|---|
| HTTP OTA (ESP-IDF `esp_https_ota`) | ESP32 | ESP32 ดึง image จาก Connect, ตรวจลายเซ็นก่อนสลับ |
| ArduinoOTA (`espota`) | ESP32/ESP8266 ที่ใช้ Arduino | ง่าย แต่รหัสผ่านอ่อน — ใช้ในวงทดสอบเท่านั้น |
| BLE DFU | nRF52 | ภายหลัง |

**กฎที่ห้ามข้าม**
- **ต้องย้อนกลับได้เอง:** ใช้ ESP32 partition แบบ A/B + rollback — image ใหม่ต้องเรียก "ยืนยันว่าใช้ได้" หลังบูต
  (เช่นหลังส่ง `hello_ack` ให้ Connect สำเร็จ) ไม่งั้นบูตครั้งถัดไปกลับไปรุ่นเดิม
  บอร์ดที่อยู่ไกลแล้วแฟลชพัง = ต้องเดินไปเสียบสาย
- **image ต้องเซ็น:** firmware lib ฝัง public key ตอนแฟลชผ่านสายครั้งแรก OTA รับเฉพาะ image ที่เซ็นด้วยกุญแจคู่กัน
  ไม่งั้นใครในวง WiFi เดียวกันก็แฟลชของตัวเองได้
- **แฟลชต้องได้สิทธิ์แยก** จากการสั่งงาน — โปรดักต์ตัดสินผ่าน `authorize` ดู [safety.md](safety.md)

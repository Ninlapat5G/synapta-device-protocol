# คู่มือ SDP: เขียนโปรแกรมแล้วอัปโหลดลง ESP32 ผ่าน Wi-Fi

คู่มือนี้คือข้อความเดียวกับที่ `sdpo guide` แสดง และที่ AI อ่านผ่าน tool `sdp_ota_guide`
แต่ละหัวข้อเปิดดูแยกได้ เช่น `sdpo guide code`

## start: เริ่มตรงนี้

SDP ทำให้ ESP32 รับโปรแกรมใหม่ผ่าน Wi-Fi ได้ ไม่ต้องเสียบสายทุกครั้ง มีแค่ 3 ขั้น:

1. **เตรียมบอร์ด** ทำครั้งเดียวต่อบอร์ด: เสียบ USB แล้วจับคู่ → `sdpo guide board`
2. **เขียนโปรแกรม** สร้างโปรเจกต์ แล้วแก้ไฟล์ `main/app.c` ไฟล์เดียว → `sdpo guide code`
3. **Build แล้วอัปโหลด** กดปุ่มเดียว หรือสั่ง AI → `sdpo guide upload`

ติดปัญหา: `sdpo guide trouble` · เช็กว่าเครื่องพร้อมไหม: `sdpo doctor`
AI ที่ทำงานแทนคนให้อ่าน `sdpo guide agent`

คำสั่ง `sdpo` อยู่ที่ `tools\sdp-ota\sdpo.cmd` ใน repo SDP (ถ้าพิมพ์แล้วไม่เจอ ใช้ path เต็มของไฟล์นี้)

## board: เตรียมบอร์ดใหม่ (ทำครั้งเดียว)

บอร์ดต้องมีเฟิร์มแวร์ SDP และจับคู่กับเครื่องนี้ก่อน หลังจากนั้นอัปโหลดผ่าน Wi-Fi ได้ตลอด

**ทางหน้าเว็บ Synapta Code (ง่ายสุด)**
1. เสียบบอร์ดเข้าคอมเครื่องที่รัน Synapta Code ด้วยสาย USB
2. เปิดหน้า Connect → กด **เพิ่มเครื่อง** → เลือกแท็บ SDP
3. เลือกพอร์ต USB ของบอร์ด ใส่ชื่อ Wi-Fi และรหัส (2.4 GHz เท่านั้น) แล้วกดจับคู่
4. บอร์ดรีสตาร์ต ต่อ Wi-Fi แล้วขึ้นในรายการอุปกรณ์พร้อมป้าย SDP ถอดสายได้เลย

**ทาง terminal** (บอร์ดใหม่ที่ยังไม่มีเฟิร์มแวร์ SDP)
```
sdpo ports
sdpo setup --port COM3 --firmware sdp-esp32-firmware.zip --key-dir KEYS --ssid "ชื่อ Wi-Fi" --no-backup
```
ไฟล์เฟิร์มแวร์ ZIP อยู่ในหน้า release ของ SDP ส่วน `KEYS` คือโฟลเดอร์เก็บกุญแจของบอร์ด ห้ามแชร์และห้ามใส่ Git

- บอร์ดที่จับคู่แล้วจะไม่โผล่ตอนสแกนหาเครื่องใหม่ (ตั้งใจให้เป็นแบบนั้น) จะกลับมาโผล่ก็ต่อเมื่อยกเลิกการจับคู่
- เครื่องอื่นที่ไม่มีกุญแจของบอร์ดจะอัปโหลดลงบอร์ดนี้ไม่ได้

## code: เขียนโปรแกรม

**1. สร้างโปรเจกต์** (ครั้งแรกครั้งเดียว) ได้โฟลเดอร์ที่พร้อม build:
```
sdpo new D:\firmware\blink --example blink
```
ไม่ใส่ `--example` จะได้โปรเจกต์เปล่า ดูตัวอย่างทั้งหมดได้ด้วย `sdpo new --list`

**2. แก้ไฟล์ `main/app.c` ไฟล์เดียว** ไฟล์อื่นเป็นของ SDP (Wi-Fi และการอัปโหลด) ไม่ต้องแตะ

```c
#include "driver/gpio.h"
#include "freertos/FreeRTOS.h"
#include "freertos/task.h"
#include "sdp_app.h"

void app_start(void)              // SDP เรียกครั้งเดียวตอนบอร์ดเปิด
{
    gpio_reset_pin(GPIO_NUM_2);
    gpio_set_direction(GPIO_NUM_2, GPIO_MODE_OUTPUT);
    for (;;) {                    // วนตลอดได้
        gpio_set_level(GPIO_NUM_2, 1);
        vTaskDelay(pdMS_TO_TICKS(500));   // ต้องมี delay ในลูปเสมอ
        gpio_set_level(GPIO_NUM_2, 0);
        vTaskDelay(pdMS_TO_TICKS(500));
    }
}
```

กฎที่ต้องจำ:
- ในลูปต้องมี `vTaskDelay(...)` เสมอ ถ้าไม่มี Wi-Fi และการอัปโหลดครั้งต่อไปจะค้าง
- ห้ามใช้ `delay()` หรือ `setup()/loop()` แบบ Arduino: ที่นี่เป็น ESP-IDF ใช้ `vTaskDelay(pdMS_TO_TICKS(ms))`
- LED บนบอร์ด ESP32 DevKit ส่วนใหญ่อยู่ที่ GPIO 2
- อย่าใช้ GPIO 1 และ 3 (สาย USB ใช้อยู่) และ GPIO 6–11 (ต่อกับ flash)
- `printf(...)` ใช้ได้ ข้อความออกทางสาย USB ที่ 115200
- ใช้ไลบรารีของ ESP-IDF ได้ทั้งหมด เช่น `driver/gpio.h`, `driver/ledc.h` (PWM), `driver/i2c_master.h`

**3. บันทึกไฟล์** แล้วไป `sdpo guide upload` ไม่ต้อง commit เอง ระบบเก็บสำเนาโค้ดทุกครั้งที่ build

## upload: Build แล้วอัปโหลด

ระบบส่งโค้ดไปคอมไพล์บนเครื่อง build (มี ESP-IDF และกุญแจเซ็นเฟิร์มแวร์) แล้วอัปโหลดลงบอร์ดผ่าน Wi-Fi และรอจนบอร์ดรีสตาร์ตเป็นโปรแกรมใหม่ ครั้งแรกใช้ราว 3–5 นาที ครั้งต่อไปราว 1 นาที

**ทางหน้าเว็บ Synapta Code**
1. หน้า Connect → แตะบอร์ด (ป้าย SDP) จะเปิดหน้า Firmware ของบอร์ดนั้น
2. ช่อง **โฟลเดอร์โปรเจกต์** ใส่โฟลเดอร์ เช่น `D:\firmware\blink` แล้วกดบันทึก (ทำครั้งเดียว)
3. กด **Build แล้วอัปโหลด**

**ทางสั่ง AI** พิมพ์ประมาณว่า:
> อัปโหลดโปรเจกต์ D:\firmware\blink ลงบอร์ด testesp32

**ทาง terminal** ใช้เมื่อมีไฟล์ `sdp_ota.bin` ที่ build ไว้แล้ว:
```
sdpo upload --device-id ID --key-dir KEYS --image sdp_ota.bin
```

ผลลัพธ์ที่ได้:
- **verified** สำเร็จ บอร์ดรันโปรแกรมใหม่แล้ว
- **build_failed** คอมไพล์ไม่ผ่าน บอร์ดไม่ถูกแตะ ผลจะบอกไฟล์ บรรทัด และข้อความ error ให้แก้แล้วกดใหม่
- **rolled_back** โปรแกรมใหม่พังตอนเปิดเครื่อง บอร์ดเลยกลับไปใช้โปรแกรมเดิมเอง (ดู `sdpo guide trouble`)
- **failed** ส่งไม่สำเร็จ บอร์ดยังรันของเดิม
- **unknown** ส่งแล้วแต่ยืนยันผลไม่ได้ ให้กดดูสถานะบอร์ดก่อนลองใหม่

อยากย้อนกลับไปโปรแกรมเก่า: หน้า Firmware มีรายการ build เก่าทุกตัว กดอัปโหลดตัวที่ต้องการได้เลย

## trouble: แก้ปัญหา

- **คอมไพล์ไม่ผ่าน** อ่านบรรทัด `app.c:12:5: error: ...` ตัวเลขแรกคือบรรทัด ที่เจอบ่อยคือลืม `#include` หรือพิมพ์ชื่อฟังก์ชันผิด
- **rolled_back** โปรแกรมพังหรือค้างตอนเปิดเครื่อง เช่น ลูปไม่มี `vTaskDelay` ใช้ขาที่ห้ามใช้ หรืออ่านหน่วยความจำผิด แก้แล้วอัปโหลดใหม่ได้เลย บอร์ดยังปลอดภัย
- **บอร์ดขึ้น offline** เช็กว่าบอร์ดมีไฟ และอยู่ Wi-Fi เดียวกับคอม ถ้าเพิ่งอัปเดตเฟิร์มแวร์ SDP ให้อัปเดต Synapta Code ให้ใหม่ด้วย
- **"Set the build machine"** เจ้าของระบบต้องตั้ง `builder` ใน `sdp-ota.json` ของ Synapta Code (ดู docs/esp32-ota.md)
- **"Set the source folder"** ใส่โฟลเดอร์โปรเจกต์ในหน้า Firmware หรือบอก AI ว่าโปรเจกต์อยู่ที่ไหน
- **โปรเจกต์ที่สร้างก่อน SDP รุ่นล่าสุด** รัน `sdpo new <โฟลเดอร์> --refresh` เพื่ออัปเดตไฟล์ของ SDP โดยไม่แตะ `app.c` ถ้าไม่ทำ บอร์ดจะได้โปรโตคอลรุ่นเก่ากลับไป
- **อัปโหลดผ่าน Wi-Fi ไม่ได้เลย** ทั้งที่บอร์ดออนไลน์: กุญแจของบอร์ดอาจไม่อยู่บนเครื่องนี้ ต้องจับคู่ผ่าน USB บนเครื่องนี้
- **บอร์ดเงียบหลังอัปโหลดโปรแกรมที่ค้าง** ถอดปลั๊กแล้วเสียบใหม่ บอร์ดจะกลับไปโปรแกรมเดิมที่ใช้ได้
- เช็กความพร้อมทั้งหมดในคำสั่งเดียว: `sdpo doctor --key-dir KEYS`

## agent: สำหรับ AI ที่ทำงานแทนคน

ลำดับที่ถูกต้องเมื่อถูกขอให้ "อัปโหลดโค้ด X ลงบอร์ด":

1. `sdp_ota_boards` หาบอร์ด ใช้ `deviceId` (16 ตัวอักษร) ไม่ใช่ชื่อ
2. ยังไม่มีโปรเจกต์ → รัน `sdpo new <โฟลเดอร์> [--example blink]` (ดูตัวอย่างด้วย `sdpo new --list`)
3. เขียนโปรแกรมใน `main/app.c` เท่านั้น ใน `app_start()` ตามกฎใน `sdpo guide code`
   **ห้ามแก้ `main/sdp_ota.c`** (โปรโตคอล ถ้าพังบอร์ดจะรับอัปโหลดผ่าน Wi-Fi ไม่ได้อีก)
   แก้ `main/CMakeLists.txt` เฉพาะตอนต้องเพิ่มไฟล์ .c หรือ component ที่ไม่อยู่ใน `driver`
4. `sdp_ota_build_upload({ deviceId, sourceFolder })` ทำครบทั้ง build และอัปโหลด ไม่ต้อง commit เอง
5. อ่านผล:
   - `build_failed` → แก้ตาม `errors` แล้วเรียกใหม่ (บอร์ดไม่ถูกแตะ)
   - `rolled_back` → โปรแกรมพังตอนเปิดเครื่อง แก้แล้วเรียกใหม่
   - `unknown` → เรียก `sdp_ota_status` ก่อนลองใหม่
   - `verified` → บอกผู้ใช้ว่าบอร์ดรัน build ไหนอยู่
6. รายงานผู้ใช้เป็นภาษาของผู้ใช้ ห้ามแสดงกุญแจของบอร์ด
